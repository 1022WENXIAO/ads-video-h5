新视频制作使用[可编程动效V2](programmable-animation.md)。下述固定节点协议只用于读取旧工程，不再作为新视频的主要制作方式。

# 轻剪中的模板执行

原始 SKILL.md 与 starter 完整保留。轻剪读取本 Skill、动效设计、工程接口及本文，通过结构化工具提交新主题的确定性状态模型。网页和成片共用 assets/integration 中的渲染器。

## 提交模型

调用 submit_science_scene，提交 config。输出由服务端渲染与校验，不提交或执行任意 JavaScript、Shell 或 HTML。

- title 最多14字、subtitle 最多28字、kicker 最多28字、prompt 最多30字、footerNote 最多28字、author 最多24字。中文和英文均计字符；长英文标题放入说明并简写标题。
- duration 默认16，可选8–64秒的整数。复杂机制使用24/32秒。bgm 默认true，无口播。
- boundary 说明事实和教学简化；basis 使用实际读到的来源URL，不编造引用。comparison 说明共同输入与比较尺度。
- panels 为4–8图，通常6图。每图 name 最多8字，english 最多10字（可留空），sub 最多18字，color 为六位十六进制颜色，difference 说明该图特有机制。
- 每图 nodes 3–10个，id 唯一。节点坐标 x/y 在[0,1]，坐标表示节点中心，映射到面板正文内部；w 在[0.12,0.8]，h在[0.1,0.26]。text 最多24字且实际字宽须放得进节点；kind 为box或token。节点应有明确含义，不用A/B/C代替真实对象。同一步的可见节点不可重叠。
- 每图 steps 为3–6步，包含 label（最多16字）、changes。第一步是输入状态，后续有可见操作和结果，最后一步停留。每个 change 指向 nodeId，可设 x/y、text、visible、active；移动、替换、移除或显示具体数据，不能所有图只有闪光。最少一项文本/位置/可见性变化。初始节点通过 visible 和 active 控制。
- 每图 transfers（1–8条）包含 from/to 节点ID和 step（1起，不能为0），用运动光点表示数据到达，在同一步结束时更新目标状态和反馈。不能与空间相隔的对象脱离。
- 每图 checks 1–6项，包含 name、step、nodeId，及期望 text/visible/active 至少一项。用于可复现示例的结果断言，例如计算结果为8、被删除草稿不可见、最终输出保持要求格式。不要声称这些检查证明真实模型效果。
- 声称JSON输出时，显示的JSON必须可被JSON.parse解析，不能写成未加引号的伪JSON。可用短字段名减少长度，但要在图内解释字段含义。用提示词要求结构化输出不等于开启供应商的JSON API模式，不使用“JSON Mode”冒充已开启该功能。

step 0为初态，后续步骤等分动画有效时长（片尾保留复位渐变）。每步前75%演示传输与移动，后25%显示接收后的状态和说明；说明逐步出现。空间随4/6/8图自动布局，但应减少8图的元素数量。

围绕用户主题设计新的节点、状态变化、比较目标和断言，不能把已有主题只换标题。若用户只要方案，提交同样的config供后续继续，服务端暂不渲染。输出保持单页循环；用户未要求发布时不自动发布。

LLM Prompt案例适合对比直接提问、明确指令、提供上下文、少样本示范、显式中间步骤、结构化输出等可组合策略。使用共同的简单任务演示输入信息如何改变可见过程与输出约束，说明这是人为设定的教学演示，不是真实推理日志、性能评分或对内部思维的观察。核对论文/官方文档，不将措辞写成质量保证。
