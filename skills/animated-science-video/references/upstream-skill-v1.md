# 动态图科普视频制作

目标：让观众看出各方法“输入是什么、做了哪一步、哪些状态变了、结果有何差异”。复制整个本技能目录即可迁移；可执行模板不依赖原作者目录、账号或其他skill。

## 先确定比较目标

沿用用户已确认的题目、版式和修改范围。若只要求改一张图，保留其他图；若要求检查其他图，先指出各图的理解缺口再针对性补动作。优先用同一输入和统一度量比较4–8种主流机制，通常6图；不足4种可比较机制的选题应合并或更换，不能用装饰凑图。

为每图写一句观众应理解的差异，再定义“初始状态 → 操作 → 结果”。教学例子的数字、阈值、计数、直方图和概率必须来自同一可复现模型。主题资料应使用论文或官方文档核对；在工程中标明教学简化，不把示意图当成真实模型推理结果。

详细表达模式与已经验证过的修订案例见[动效设计](references/animation-design.md)；仅修改某类图时读对应部分。

## 制作约定

本系列默认1080×1920、30fps、暗色、每页4–8图；上下约220px以上留白，6图优先。标题直接说明主题或图示类型，中文名后可加规范英文缩写，不能编造缩写。字形与图标不做非等比缩放；文字放不下时删减文案或重新布局，不能横向压扁。

- 操作必须可见：移动数据、选中目标、剪断/合并/取整/更新/遗忘等，不能只有连线或文字切换。
- 先显示当前步骤需要的信息。文字按数据流以1、2、3逐步揭示；首轮完成后可保留中间说明，后续数据继续更新结果指标。
- 光点到达后，目标节点闪光、描边或轻微动作，表示收到数据。状态变化与接收时刻一致。
- 一个动态页面导出一个视频，只循环当前页，不拼接主题、不自动翻页。时长通常16秒；复杂过程可24/32秒或更长，不为凑16秒加速到看不清。激活函数示例8秒一轮、16秒两轮。
- 保持无口播，按视频时长循环BGM，不改变音乐速度与音高。模板附本项目现用16秒循环母带与来源信息；使用者可以换音乐。署名可配置，在原项目继续制作时沿用“by轻喵制作”，给其他作者制作时使用其指定署名。

## 从可运行工程开始

先读[运行与迁移](references/replication.md)，检查现有Node、Canvas、FFmpeg和中文字体。优先复用已有依赖；发现缺失时列明所需安装和环境影响，不直接做大下载。

```bash
python3 <skill-dir>/scripts/create_project.py <new-project-dir> --scene compression --author "by作者制作"
cd <new-project-dir>
# 首次需要安装固定版本Canvas依赖；已有依赖可按迁移文档复用
npm install
npm run preview
npm run render -- configs/compression.json
npm run verify -- configs/compression.json
```

六图示例将`compression`改为`activations`。网页预览和MP4使用相同`renderer.mjs`。新主题需要实现自己的纯时间状态模型与`paintPanel`并注册scene；仅换JSON标题不会自动生成新的科学过程。接口和文件用途见[工程接口](references/project-api.md)。

在本项目，工程归入`资讯/动态图科普视频/<系列>/episodes/<版本>/`，当前交付放`Downloads/资讯/动态图科普视频/<系列>/成片/`，可编辑源码与旧版本放`工程与版本/`。其他人的项目按其目录约定，不创建原作者绝对路径。

## 验收和交付

运行模板的模型检查、全帧布局检查、渲染和媒体验证。再打开实际成片正常速度观看一个完整循环，检查手机尺寸、过程定位和BGM；技术检查通过不等于观众已看懂。

重点看“操作之前 / 操作中 / 操作之后”三态，尤其是剪枝、掩码细化、记忆遗忘和参数更新。像素有变化不证明机制讲清；若画面只是闪动，应继续修订。

保留MP4、封面、配置、状态/绘图代码、事实依据和边界、源文件哈希及检查结果，标为待用户审阅。先交付一条样片再按用户授权继续系列。不要因制作完成自动上传、建定时任务、删除已发布作品；发布需使用者单独授权。
