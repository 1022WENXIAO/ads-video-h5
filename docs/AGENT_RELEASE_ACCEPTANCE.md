# Agent 发布成片验收

后台「Agent 能力评测 → 发布验收」配置每次新版本的自动测试。有 `dist/release.json` 的发布服务启动后使用部署版本号建立唯一发布记录，由后台已配置的文本模型生成自然用户指令，再通过现有 Agent、模型供应商、配音、ASR、渲染和审查链路实际制作视频。模型配置和密钥保留在服务端。不同站点在各自持久数据目录运行，账号、素材、积分和评测记录不跨站合并。没有发布 manifest 的开发启动默认不自动花费；隔离验收可显式设置 `QINGJIAN_RELEASE_EVAL_STARTUP=1`，本地界面测试可设为 `0` 禁止自动启动，后台手动验收仍可使用。

默认开启，每轮 3 例，同时覆盖热点新闻、从零生成知识视频、双视频剪辑；可设置 3–8 例。默认跟随后台文本模型，也可指定可用模型。选定模型用于生成测试指令及执行本轮任务，运行开始时固定配置快照。每例默认最长 1,800 秒、用例生成最长 180 秒、整轮最长 7,200 秒，均有可配置上下限。单版本默认最多 2 次尝试，重试由管理员明确发起；服务重启不会重复提交已开始的付费任务。

首次剪辑测试会合成两段带实际中文讲解音轨的受控示意 MP4，之后复用。每轮仍真实识别、选择片段、添加字幕、渲染、解码和审查成片。受控素材验证基础剪辑执行能力；真人复杂素材、产品宣传、多轮修改等业务能力需在「评测集」上传素材、绑定用例并运行，不能由受控素材通过推断所有业务场景通过。

受控素材使用 `controlled-semantic-v3`：真实移动小球、观测轨迹、候选原因、双轨小车、等条件比较与证据边界，画面和原声都承载可剪辑的信息。关键结论、限制和“观察≠推测”位于底部字幕安全区之外；960×540 画面预留 y=400–480 字幕带，保存并回归检查重要标签的实际位置与字号边界，避免成片字幕遮住图解信息。升级复用 v1 已付费语音，保存脚本、逐字时间或明确标注的估计时间、音频、图形和视频哈希；旧色条视频不作为新版本素材复用。出题模型获得准确素材说明，基础剪辑采用原横屏画幅，生成类覆盖横屏或竖屏。只保留所选句子的完整原话，不能把“完整原话”误解为在20秒内塞进两段全部逐字稿。

教学与新闻的 HTML 章节默认串行检查和渲染，避免小内存服务器同时启动多份 Chromium 耗尽内存；研究、配音等阶段仍保持原并发。资源充足的主机可设 `QINGJIAN_HTML_CONCURRENCY=2` 恢复双章节渲染。

模型只生成用户需求、任务类型、名称和画幅；服务器固定时长、素材绑定、通过阈值和质量检查，拒绝重复表达、绕过验收或后台操作的生成请求。新闻必须实际联网核验来源与时效，来源不可读需要恢复，无法核验时不得编造。视频只在已生成且真实检查和质量分数通过时记为通过。

自动新闻用例要求最近24小时报道的真实热点，并在画面标明实际报道日期；生成器拒绝与该窗口冲突的测试指令。普通“今天的热点”允许近24小时已核验报道，明确要求“今天发生/发布”的指令仍须当日事件正文证据。用户明确指定三天或一周等窗口时保留该窗口。新运行使用 v5 评分；历史运行与失败成片不重新评分或覆盖。

## 状态与证据

- `queued`：等待执行。
- `generating`：生成用例或准备真实素材。
- `running`：执行制作、渲染和成片验收。
- `passed`：本轮每例都有成片且全部通过验收。
- `failed`：已执行但有失败、未交付或未通过质量验收的用例。
- `blocked`：模型、素材准备、版本或其他前置条件未满足。
- `cancelled`：管理员停止或整轮执行被取消。

发布记录保留版本号、配置与模型快照、生成指令、尝试次数及评测运行 ID。「查看成片、验收分数与失败步骤」打开已有评测历史，支持受保护的视频播放、下载、原始指令、真实工具输入与结果、质量失败项和独立人工评分。历史尝试保留原失败与成片，不被新一次成功覆盖。

## 构建检查与线上验收边界

GitHub 的 `cn-release.yml` 运行完整本地回归，再构建并打包 H5、后台与小程序。回归包含网络恢复、生成用例约束、失败/中断恢复与验收门禁；本地测试中的供应商响应使用受控夹具。这一阶段不持有生产模型密钥，不执行付费的生产成片任务，也不能称为线上成片验收通过。

真实成片验收由已部署的新服务启动后在该服务器执行。新版本在验收期间可能已提供服务，因此自动验收记录本身属于部署后验证。国外 `qingjian-cd` 与国内 `activate-release` 在健康检查后读取受保护的本地验收记录，等待对应 SHA 三类成片全部通过；失败或超时沿用现有部署回滚机制。国外 CD 单元等待上限调整为 9 小时，以覆盖后台可配置的最多 8 小时验收加构建与记录等待；安装更新后的 CD 脚本和单元并执行 `systemctl daemon-reload` 后生效。HTTP 健康检查通过只表示服务可用。没有一份符合预期提交号、三类能力均有成片且全部通过的记录时，不应报告发布验收成功。

每次用户任务执行也保存独立 `attemptId`、版本、模型、开始结束时间、工具 trace 与已脱敏连接错误。手动重试和重启保留旧尝试；已有作品标为沿用或重新审查，避免把旧作品算成本次新生成。轮询状态只返回尝试摘要，完整工具记录通过已有登录权限保护的 `/api/jobs/:id/attempts/:attemptId` 按需读取。

基础剪辑的真实渲染、独立审查、按反馈重新规划与返修后复查也会写入工具 trace，不能只看到最初方案。默认逐段和混音响度归一化，只有用户明确禁止相应音频处理才关闭；保留原声不会自动关闭响度处理。完整原话需求进入完整句精剪校验，必要的结论限制不能因为独立 ASR 句子完整就被省去。规划错误反馈可附最多两组经真实源边界、padding 和最终校验验算的完整句时长候选，由模型继续决定叙事；剪辑规划最多允许五次参数校验拒绝，仍受12轮/360秒限制，其他工具保持原来三次上限。

精剪状态机的可修复时长或完整句编排拒绝会退回选句，保留已有转写和已核验原句组；预算建议不能拆开独立完整性检查确认的合并原话组。相同源哈希、范围与句子ID的画面分析可以复用，新组重新核验。仅改理由重复提交失败组合不会触发同一编排；明确要求锁定原选句时保留该约束，不擅自删句或放宽目标时长。

新闻上下文同时提供 UTC 和完整北京时间。热榜 `observedAt` 表示榜单快照，HN `submittedAt` 表示社区提交，均不能推断首次上榜、原文发布或事件发生时间。除模型审查外，程序还检查实际旁白、章节标题和画面文字中的热榜时间断言：错误日期、时段、数字或中文时钟、跨句时间以及无来源的首次上榜表述都不能通过；已读正文确实证明的历史时间可引用。该检查同时用于脚本审查、检查点恢复、既有成片复用和最终返回，跨零点复核沿用原始指令与观察时间。

各新闻阶段的新 Agent 接收本轮实际查询、选择及历次淘汰原因，不依赖上一阶段的对话记忆。搜索同时接收原始需求、固定的 Asia/Shanghai 日历日 UTC 区间和请求截止时刻；近24小时新鲜度不替代严格的当天事件证据。普通搜索接口只接收简短关键词与日期，完整契约保存在查询记录中；联网模型接收完整契约。补齐新正文后允许重新核验同一对象，不能用相同不合格证据给旧候选换标题。

新闻读源会去掉确定的点击追踪参数，保留文章 ID、分页、语言等内容参数，并依据实际页面同站非首页 canonical 归一同一文章的 URL 别名。每轮跨查询分配最多12页、每发布方最多3页的读取预算。已有合格当日事件而只缺独立报道时，主动围绕该事件排除原发布方补查；昨日公告、无日期页面和错误型号仍不符合当日事件要求，不以降低来源门槛换取通过。

生成旁白的识别支持“双11/双十一”等特定活动名称的同值写法及上下文内已知同音词，保留原始 ASR 和听到的时间跨度；不同数字、遗漏尾字仍拒绝。识别或语义分句技术错误只对已保存的同一音频有限恢复，不据此重录或改脚本。仅生成旁白在后处理分句输出无效时可保留原 ASR 字词、时间与完整性标记，并明确记录警告，仍须通过完整脚本对齐和实际成片审查；普通上传素材精剪维持严格语义分句。初次识别和独立复听的失败原因分别保留，避免最后一个错误掩盖最初的误判。

本章已引用来源明确命名、且实际旁白使用的公司专名优先加入短 ASR 词表，并核对每次出现的完整转写及字词。专名不同或缺字不能靠整章高相似度放行，先复听同一音频；不凭期望脚本自动改写原始转写或补字。该规则覆盖明确公司命名，普通图解标签和公司泛称不当作专名，其他人名等类型仍需独立成片审查。

生成旁白在变速前后可保守收紧超限停顿：原有低能量门槛不变，只在原始波形另行确认的 -65dB 近静音中心删除必要时长，两侧各保留120ms，再执行原停顿门禁、逐词识别与声音审查；不直接剪掉整个低能量区间。裁剪坐标不使用 loudnorm 的前瞻延迟时间，多个停顿按实际输出时长统计。每次付费原始录音在被下一次重录替换前按哈希留档，损坏旧留档不能被静默接受。

普通新闻、知识与创作图解首版根据已核验实体和关系定制，数值图表、公式和曲线保留专用渲染路径。纯画面归属、对象或布局错误优先复用正确旁白重绘；声音或事实错误仍按相应路径修复。观众事实与内部设计目标、审核反馈和避免事项分开传递，节点与章节校验阻止制作话术进入实际画面；未知身份使用中性示意，不凭通用图标添加性别、职业或人数。

新闻首章的报道日期由程序从核心事实实际引用、正文逐字支持且在原指令窗口内的已核验来源生成，不能从事件日期、热榜采样或搜索摘要推断。画面在预留区域持续显示至少24px的“报道日期：YYYY-MM-DD（北京时间）”，保留示意声明。日期仅为日期的来源沿用北京时间零点解析；跨零点复核固定原用户消息时间，制作、最终审查、作品记录及部署门禁使用同一截止时刻。

成片来源时效也按原指令截止时刻判断，避免制作过程中刚好越过24小时边界造成误拒。实际查询时间单独对审查时钟验证，排队后延迟开始的合法查询不因此被判成未来；新指令仍使用新的截止时刻，研究缓存的有效期规则保持独立。

`news-date` 是零权重必过项。真实 Chromium 检查实际 HTML 的来源属性、字形、遮挡、裁切、字号和多个动画时点；独立审查还须在本次首章成片抽帧中读出正确日期。服务器绑定来源、HTML、分镜、方案与实际 MP4 哈希，模型不能自报这些证明。缺少证据，即使模型评分100或标签为 passed 也不通过；纯日期画面缺失只返修首章画面，保留正确配音。

前渲染 HTML 技术布局失败保留在分镜阶段。实际检查发现卡片标签与内部数值重叠时，可将原标签移入卡片上部空白区，保持可见文案、数值、字号和其他对象不变，再执行原检查器；无法安全调整时使用既有一次局部重绘机会。每章两次实际布局检查预算跨工具调用和重启保存，已失败布局不原样重检，已通过章节与声音按哈希复用；仍失败则保留证据停止，不能退回修改已验收旁白。独立数字节点禁止拆行，并检查实际字形宽度，不能通过缩小字号或忽略检查器放行。

2026-10-15 的原截图指令“生成今天的热点 AI 新闻视频”本地真实回归保留为失败证据：29分55秒内生成两版约45秒成片，技术解码和音视频流端点均通过，独立内容审查分别74与72分；缺陷包括专名字幕错误、数字拆行和文字遮挡，两版还遗漏了实际报道日期。该次真实供应商执行验证了问题，不能记为生产入口通过。后续修复的受控工作流测试与真实浏览器布局测试也不替代两站新版本的真实三类成片验收。

后续 `1fcbd50` 虽通过750项回归和Linux CI，真实新闻验收仍在文本阶段发现缺陷：程序把合法热榜快照、否认首次上榜的警示与报道日期误判成上榜时间断言，错误反馈又使仲裁偏离已有来源契约，最终耗尽修稿次数。字数超限已被Agent自主修复，不能归为最终根因。独立原截图指令的研究还发现第一财经、36氪标题署名行中的有效发布时间被漏读；保留原HTML的离线重放确认了该解析缺口。

该轮新闻保留真实失败，知识与剪辑在媒体生成前安全停止，未产生配音、识别、HTML、成片或分数；国内恢复稳定版。新增回归使用实际标题署名结构及原始快照文本，仍拒绝正文事件日期、网站时钟、更新时间、歧义日期和无证据首次上榜，不能用放宽时效或改分替代修复。

`aebbf53c` 通过759项回归与Linux CI，但后续国内真实三例仍为0/3通过。新闻与知识已完成真实配音、识别和部分分镜，最终分别因日期卡片正文重叠、猜想卡标题与内部圆节点重叠而停止，均没有最终成片。精剪自主修正了首轮时长超限并实际导出20.2秒视频，完整解码和音视频流端点通过；评测80分、独立审查82分仍为未通过：段内9.0 LU超过8 LU，实际抽帧还确认底部动效与字幕及源标注重叠。该发布自然失败并回滚，历史分数与原始证据保留。

同版本的独立原截图指令在5分35秒内完成研究并进入脚本，但因预算与真实新稿引用反馈不完整，以及“本次核验的榜单观察，不代表首次上榜”被误拒而耗尽修稿次数；没有合成音视频。研究通过使用的是既有JSON-LD发布时间入口，不能把这次成功归因为新增标题署名解析。后续热榜校验按局部谓词归属与否定范围处理报道日期、事件日期、观察时间和进入榜单断言，仍拒绝错误年份、日期、时分秒及无正文证据的肯定上榜；源正文否认中的同一词串也不能证明相反断言。

脚本反馈现在统一实际已分配的预算，同时报告章数及各章超限，分别说明研究缺失与核心事实未引用真实新稿；候选引用只来自本轮已读研究，不自动添加事实或无关来源，六次修稿上限保持。布局恢复新增真实失败卡片的内容区重排及标题上移，保留原文、数字、字号、路径与内部图形，仍由第二次实际HTML检查决定通过，不能重录正确旁白来修几何。普通文字节点的实际零内边距与绘图契约一致，原始失败布局保留为回归夹具。原视频响度处理先尝试原温和档，测得不合格才试一个适度档；同一真实受控原声窗口实测7.4 LU、时长不变，8 LU门槛保持，数值通过不代表主观听感验收。

普通精剪的字幕、叠字和局部动效共用实际几何布局。短片对真实已拼接画面的所有帧做有界、保守的背景留白检测；无法确认留白或没有安全位置时，将完整源画面等比置入独立文字区之间，不裁掉画面或隐藏文字。动作、描边及字幕上移计入各自边界，实际字形回归覆盖中文、宽英文、emoji和数字；教学及原声重构保持专用字幕路径。渲染清单记录留白分析、实际文字位置和是否缩放源画面，缩放后的可读性仍须真实成片审查。本地同源同方案的20.2秒重合成已完整解码并人工检查首中尾，未缩源且原标注、字幕、动效互不遮挡；它属于局部技术修复验证，不能覆盖旧失败或计入新发布通过率。

## 部署门禁命令

国外自动部署失败时会在 `/var/cache/qingjian-cd/rejected-sha` 保留失败提交号，后续定时检查不再反复切换和回滚同一版本。新提交自动恢复发布；同一提交的人工重试须同时核对失败标记和后台验收尝试，不能删掉失败证据冒充通过。部署工具在成片验收前后都核对服务实际运行的 SHA。会话存储读取或 JSON 异常会保留原文件并拒绝启动，不能初始化空数据覆盖。

Linux 回归使用已有可执行 Chrome 和中文字体，不能依赖测试时隐式下载浏览器。国外 CD 如需复用服务用户的私有浏览器缓存，只复制浏览器 bundle 到独立构建缓存，不开放生产数据目录。帧时间检查直接解码读取 FFprobe JSON，避免从交织的音视频调试日志推断帧数或时长。

实际评测还读取音视频 packet 的时间戳与持续时间，检查各流实际起点、终点及音画尾差；技术目标使用执行方案的时间线长度，容差为0.25秒。该项不增加分数，但缺失或失败都不能通过，不能用正常的容器总时长掩盖画面提前结束。用户目标时长仍按原用例容差单独检查。混合硬切与叠化的回归同时验证真实帧终点和切换后的素材内容，包括32镜短片压力例。已预切为固定帧率的素材在叠化前不重复执行 `fps`，独立叠化链按累计帧边界裁切后再拼接，防止 EOF 提前结束或逐链舍入累计偏移。

国外部署回滚会区分依赖尚未切换和已完成切换两种状态，前者保留原依赖目录，后者恢复备份；回归使用真实临时目录检验两种失败路径及 SIGTERM 中断。两站部署脚本收到 INT、TERM 或 HUP 都会按非零退出执行既有回滚，独立部署单元应留足停止时间完成恢复。

`pnpm eval:release` 读取现有受保护管理员接口，不增加公开后门。凭证为已认证的管理员短期会话，存于私有 `0600` 文件中（文件只包含会话字符串），或通过受保护环境变量 `QINGJIAN_ADMIN_SESSION` 传入；二选一。管理员二次验证仍走现有登录流程，旧长期 `admin-token` 不可替代会话。不要将会话放入 URL、命令行参数、仓库、构建包或 CI 输出。会话失效会返回非零退出码，不能当作测试成功。

```bash
QINGJIAN_ADMIN_SESSION_FILE=/run/qingjian/release-admin-session \
pnpm eval:release \
  --url https://video.tensorbytes.com/qingjian/api/admin/evaluations \
  --revision <40位部署提交号> \
  --start \
  --timeout-seconds 7500
```

服务器本地可使用 `http://127.0.0.1:8787/api/admin/evaluations`；其他 HTTP 地址、含凭证或查询参数的 URL、重定向均被拒绝。国外站使用各自域名与会话。`--start` 在核对实际部署版本后幂等确保本版本验收记录；不会重试失败任务。省略 `--start` 时只等待启动自动验收。自动验收关闭、版本不一致、缺少通过证据、失败、阻塞、取消、API 失联或等待超时均返回非零。超时不会取消服务器仍在执行的任务；先在后台检查进度再决定是否停止，避免重复提交付费制作。

该命令只输出版本、状态、任务 ID 和成片统计，不输出会话、供应商密钥或完整响应正文。部署系统应保留退出码与发布记录链接；不能只用进程正常启动、构建成功或请求选路测试代替视频制作验收。

## 服务器本地门禁

部署程序已有服务器文件权限时，可直接读取该站点的私有评测存储，无需管理员登录、会话自动续期或额外接口：

```bash
node --import tsx tooling/release-acceptance.ts \
  --data-dir /data/qingjian \
  --revision <40位部署提交号>
```

本地模式不能同时使用 `--url` 或 `--start`，也不读取管理员凭证。服务正常启动后自动建立验收记录；部署脚本须另外核对运行服务、`dist/release.json` 与健康检查的提交号，本地文件读取不能证明实际监听进程运行哪个版本。

门禁读取 `evaluations/releases.json` 及 `evaluations/index.json`，核对发布、执行次数、实现指纹、运行版本、三类生成指令、原始用例哈希、全部质量检查、独立审查分数和真实成片元数据。缺少视频哈希、文件大小、有效时长或指定双素材绑定时均拒绝通过。视频全帧解码及制作清单验证仍由实际评测引擎完成，部署脚本读取其已保存的证据。默认等待时间为本轮 `maxSuiteSeconds + 300` 秒，最多 29,100 秒；可用 `--timeout-seconds` 明确覆盖。错误或超时返回非零，不取消服务器任务。
